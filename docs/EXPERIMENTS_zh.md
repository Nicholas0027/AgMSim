# 有区分度的实验：设计与结果

之前的等级扫描和 2×2 都没有显著差异。本文档记录为此重新设计的一组对照实验，以及在本机实际跑出的结果。全部实验可用一条命令复现：

```bash
.venv/bin/python experiments/suite.py --seeds 10 --workers 8
```

场景文件在 `experiments/scenarios/`，实验定义在 `experiments/suite.py`，结果表和原始数据在 `experiments/results/`。

## 一、之前为什么看不出差异

1. **能力互相掩盖。** 城市场景里运营方一发通告，L0 的车也会绕开事故，于是"车会不会改道"不再重要。
2. **权限没有用武之地。** 没有收费，L2 就没有时间与金钱可权衡；公交和小汽车一样堵，L3 就没有理由提议换乘；电量充足，L4 就无站可选。
3. **没有做配对比较。** 各组用的是同一批种子，却按独立样本算置信区间，种子之间的差异淹没了组间差异。
4. **一个时序问题。** 车在出发的那一拍就驶上了默认路线的第一段，轮到它决策时已经来不及，白白绕一段。这是实现上的缺陷，已修正：有路线决定权的车先决策再起步。

## 二、设计原则

- **一个实验只回答一个问题**，只改变与问题相关的一到两个因素。
- **给被检验的权限创造起作用的条件**：事故、收费、瓶颈加公交专用道、充电紧张。
- **其余主体设为 L0**，避免掩盖。
- **需求固定**：出行者设为 L0 且人人有车，所有组面对同样的出行。
- **配对比较**：各组共用种子，报告与基准组的逐种子差值及其 95% 置信区间。
- **预先指定主要指标**，其余指标只作辅助说明。

这些实验回答的是"这项权限**能不能**起作用"，不是"它在真实城市里起多大作用"。场景是为放大效应而构造的，非 LLM 策略是参数未经标定的启发式，效应大小不能外推。

## 三、实验一览

| 实验 | 检验的 agency | 场景条件 | 主要指标 | 结论 |
| - | - | - | - | - |
| incident | 车 L1 改道、运营方 L1 通告 | 主干道长时间事故 | 平均出行时间 | 两者任一即可，互为替代 |
| penetration | 车 L1 的占比 | 同上 | 平均出行时间 | 随占比近似线性下降，没装的车也受益 |
| toll | 车 L2 知道车主偏好 | 中心区固定收费 | 收费总额、广义成本 | 收费减半，广义成本下降 |
| bottleneck | 车 L3 提议换乘、人 L2 回应 | 过桥瓶颈加公交专用道 | 平均出行时间 | 时间减少 21% 到 35% |
| charging | 车 L4 自选充电站、站 L1 定价 | 充电紧张 | 每次充电排队时间 | 车选站使排队减少九成；站单独调价只增加收入 |
| self_charging | 车 L4 空驶充电 | 同上 | 车公里、出行时间 | 车公里增加 23% 到 51%，拖慢其他人 |
| signals | 信号灯 L1/L2、协调者 L2 | 全路口有信号灯，东西向车流占主导 | 平均出行时间 | 灯自己决策 −21 秒；固定配时但听协调者 −9 秒；灯不听则协调者无效（第八节） |
| ondemand | 按需车 L1 改道、L2 拒单、L4 调度 | 无私家车，50 辆按需车，需求集中在中心 | 平均等车时间 | 改道 −10 秒；逐利拒单 −21 秒且空驶减少；主动调度没有再缩短等待，空驶增加（第九节） |
| places | 外部事件（不是 agency 对比） | 有场所的小城：下雨、散场、封路 | 平均等待时间 | 单独发生各 +6、+12、+0 秒；同时发生 +57 秒，是各自之和的三倍（第十节） |
| day_plan | 人当天改日计划 | 傍晚活动链加单桥事故 | 计划得分（美元） | 事故每人损失 3.32 美元，改计划挽回 0.27 美元，迟到减四成（第七节） |

以下各表均为 10 个种子的均值；括号内是与基准组的配对差值 ± 95% 置信区间半宽，`*` 表示区间不含 0。

## 四、各实验结果

### incident：谁有 agency 才能避开事故

6×6 路网，300 人全部开车，中央主干道及相邻路段在第 5 到 35 分钟降速到一成。

| 实验组 | 平均出行时间（秒） | 90 分位（秒） | 改道次数 |
| - | - | - | - |
| 车 L0 · 运营方 L0（基准） | 923 | 1855 | 0 |
| 车 L1 · 运营方 L0 | 265 (−658 ± 37)* | 400 (−1455 ± 31)* | 171 |
| 车 L0 · 运营方 L1 | 266 (−657 ± 38)* | 393 (−1462 ± 33)* | 0 |
| 车 L1 · 运营方 L1 | 266 (−657 ± 37)* | 394 (−1461 ± 29)* | 11 |

- 只要车或运营方中有一方有 agency，平均出行时间就减少约 71%。
- 两者同时具备没有额外收益：通告发布后，L0 的车靠公开信息就能绕路。
- 这说明 agency 放在车上还是放在设施上是一个可以用本平台研究的设计问题。

### penetration：会改道的车占多大比例

同一场景，运营方 L0，L1 车的占比从 0 到 100%。占比提高时只增加车辆，原有的 L1 车不变。

| L1 占比 | 平均出行时间（秒） | L0 车：车程/自由流 | L1 车：车程/自由流 |
| - | - | - | - |
| 0%（基准） | 923 | 5.71 | – |
| 25% | 724 (−199 ± 22)* | 5.40 (−0.31 ± 0.20)* | 1.71 |
| 50% | 549 (−374 ± 21)* | 5.09 (−0.63 ± 0.20)* | 1.70 |
| 75% | 379 (−544 ± 30)* | 4.35 (−1.37 ± 0.31)* | 1.68 |
| 100% | 265 (−658 ± 37)* | – | 1.64 |

- 总体出行时间随占比近似线性下降。
- 没装的车也受益：别的车绕走后，事故路段没那么堵了。
- 装了的车在任何占比下都接近 1.7，没有出现"大家一起改道反而更堵"的现象。这个路网备选路线多，结论未必适用于备选少的路网。

### toll：知道车主偏好的车

7×7 路网，中心区是快速路但收费 0.6 美元，绕行免费但慢。240 人从西侧到东侧，全部开车。

| 实验组 | 收费总额（美元） | 平均出行时间（秒） | 低时间价值者广义成本 | 高时间价值者广义成本 | 与车主利益一致率 |
| - | - | - | - | - | - |
| 车 L1，只求快（基准） | 113.6 | 262 | 1.99 | 3.76 | – |
| 车 L2，算法 | 53.6 (−60.0 ± 2.3)* | 270 (+8.3 ± 1.8)* | 1.81 (−0.18 ± 0.01)* | 3.59 (−0.17 ± 0.02)* | 100% |
| 车 L2，规则（仍只求快） | 108.3 (−5.3 ± 1.3)* | 259 (−3.0 ± 0.6)* | 1.96 (−0.03 ± 0.01)* | 3.71 (−0.05 ± 0.02)* | 41% |

- L2 的车替车主权衡后，缴费总额减少一半，平均多花 8 秒，广义成本显著下降。
- **"与车主利益一致率"是一个不依赖总体结果的指标**：每次车替车主选路时，按车主自己的时间价值算出各路线的成本，看车选的是不是最低的。算法按定义是 100%；同样有 L2 权限但只求快的规则只有 41%，平均每次让车主多花 0.15 美元。
- 这个指标把"有权限"和"会用权限"分开了，适合用来比较不同的 LLM。

### bottleneck：车提议换乘

两岸各 4×4 路网，两座桥，220 人几乎都要过河。一条公交线走北桥，有专用道，不受拥堵影响。

| 实验组 | 平均出行时间（秒） | 90 分位（秒） | 提议次数 | 被接受 |
| - | - | - | - | - |
| 车 L2（基准） | 1605 | 2250 | 0 | 0 |
| 车 L3，车主默认听从 | 1043 (−562 ± 32)* | 1592 (−658 ± 76)* | 94 | 94 |
| 车 L3，车主自行判断 | 1271 (−334 ± 55)* | 1970 (−279 ± 133)* | 95 | 33 |

- 车能提议换乘后，平均出行时间减少 35%（车主一律听从）或 21%（车主按效用模型判断）。
- 车主自行判断时只接受了 35% 的提议，因为车只按省不省时间来提议，而效用模型还要算票价，并给步行和候车加了权重。
- 人的 agency 在这里**削弱**了系统收益：听车的人越多，过桥的车越少，所有人都更快。这是一个值得用 LLM 扮演车主来研究的问题。
- **2026-11-10 修正。** 此前车辆算法拿换乘和"当前路线"比，而不是和同一次观测里列出的最快开车路线比；车主看到的"继续开车要多久"也是当前路线的时间。三个种子里 265 次提议有 151 次其实改道更快。现在换乘必须快过改道才会被列出和提议，车主看到的是最快开车时间。上表是修正后的结果，修正前为 −601 和 −399 秒，结论方向不变。其余五个实验不受影响，逐项相同。

### charging：车选站与站定价

6×6 路网，240 人全部开车，初始电量 8% 到 30%，多数车途中必须充电。中心站只有 1 个桩且在多数人的路上，另两个站各 2 个桩但偏远。

| 实验组 | 每次充电排队（秒） | 平均出行时间（秒） | 各站负荷基尼系数 | 充电站收入（美元） |
| - | - | - | - | - |
| 车 L3 · 站 L0（基准） | 855 | 426 | 0.37 | 21.6 |
| 车 L4 · 站 L0 | 86 (−769 ± 177)* | 291 (−134 ± 32)* | 0.08 (−0.29 ± 0.05)* | 23.4 (+1.7 ± 0.4)* |
| 车 L3 · 站 L1 | 855 (0) | 426 (0) | 0.37 (0) | 28.6 (+7.0 ± 0.6)* |
| 车 L4 · 站 L1 | 92 (−763 ± 183)* | 292 (−134 ± 34)* | 0.09 (−0.28 ± 0.05)* | 29.8 (+8.1 ± 1.6)* |

- 车自己选站后，排队时间减少九成，出行时间减少 134 秒，各站负荷趋于均衡。
- **充电站单独调价对出行者没有任何影响**，只是收入增加 32%：没有选站权的车只会去绕行最少的站，不管价格。
- 设施的 agency 要有对方的 agency 才起调节作用，否则只是转移支付。

### self_charging：自主充电的副作用

同一场景，车均为 L4，改变"停车后电量低于多少就自己去充"的阈值。

| 阈值 | 车公里 | 空驶占比 | 平均出行时间（秒） |
| - | - | - | - |
| 不主动去充（基准） | 536 | 0 | 291 |
| 低于 15% | 657 (+121 ± 13)* | 0.23 | 441 (+150 ± 35)* |
| 低于 25% | 783 (+247 ± 9)* | 0.37 | 366 (+75 ± 30)* |
| 低于 100% | 810 (+274 ± 12)* | 0.39 | 366 (+75 ± 32)* |

- 车主下车后车自己空驶去充电，车公里增加 23% 到 51%。
- 空车挤占道路和充电桩，其他人的出行时间增加 75 到 150 秒。
- 影响不是单调的：阈值 15% 时去充电的恰好是电量最低、与途中必须充电的车抢桩最厉害的那批。
- 这与 AgV 论文提到的"诱发车公里"风险一致，是 agency 带来负外部性的一个可度量的例子。

## 五、LLM 闭环实验（本地 Qwen2.5-7B 与 DeepSeek）

两个实验都只在被检验的决策位置上换成 LLM，其余不变，让模型驱动整段仿真。Qwen2.5-7B-Instruct 在本机用 mlx-lm 运行，3 个种子；DeepSeek 通过官方接口调用。所有模型用同一套未经调优的提示词，结论只代表这些模型在这套提示词下的表现。`--answer` 选择回答格式：`explain` 先选择后说明（默认），`reason` 先推理后选择。

```bash
.venv/bin/python experiments/suite.py llm_alignment llm_persuasion --seeds 3
```

```bash
.venv/bin/python experiments/suite.py llm_alignment --seeds 10 --llm deepseek --answer explain reason --llm-workers 12
```

```bash
.venv/bin/python experiments/suite.py llm_alignment --seeds 10 --llm deepseek-thinking --llm-workers 10
```

```bash
.venv/bin/python experiments/suite.py llm_persuasion --seeds 5 --llm deepseek --answer explain reason --llm-workers 12
```

### llm_alignment：LLM 驱动的车是否按车主利益行事

收费场景缩小到 60 人，车均为 L2，能看到车主的时间价值和各路线的时间与收费。括号内是与同批种子的算法基准的配对差值。灵敏度的定义见第六节：车主该付费时付了的比例，减去不该付时付了的比例。

| 决策模型 | 种子数 | 选择次数（合计） | 与车主利益一致率 | 灵敏度 | 平均每次让车主多花（美元） | 回退 |
| - | - | - | - | - | - | - |
| 算法（基准，按定义一致） | 10 | 503 | 100% | 1.00 | 0 | 0 |
| 规则（只求快） | 10 | 503 | 49.0% (−51 ± 5 个百分点)* | 0.15 | 0.10 (+0.10 ± 0.01)* | 0 |
| DeepSeek-Flash，先选择后说明 | 10 | 503 | 49.6% (−50 ± 5 个百分点)* | 0.16 | 0.10 (+0.10 ± 0.01)* | 0 |
| DeepSeek-Flash，先推理后选择 | 10 | 503 | 50.7% (−49 ± 5 个百分点)* | 0.18 | 0.09 (+0.09 ± 0.02)* | 0 |
| DeepSeek-Flash，思考模式 | 10 | 503 | 80.9% (−19 ± 4 个百分点)* | 0.65 | 0.03 (+0.03 ± 0.01)* | 0 |
| Qwen2.5-7B，先选择后说明 | 3 | 152 | 51.4% (−49 ± 23 个百分点)* | 0.15 | 0.10 (+0.10 ± 0.05)* | 0 |

- **不带思考的模型与"只求快"的规则没有差别。** Qwen 的结果与规则逐种子完全相同；DeepSeek-Flash 的两种回答格式在 503 次选择里分别只比规则多对了 3 次和 8 次。（后来做对照时发现，这与路线各字段的先后顺序有关：把收费写在时间前面，Qwen 的一致率从 55% 升到 79%，见第十二节“路线身份有没有副作用”。）
- **开启思考模式后一致率升到 81%**，平均每次让车主多花的钱从 0.10 美元降到 0.03 美元，收费总额每次运行 19.0 美元，介于算法的 13.4 和规则的 27.5 之间。
- 所有模型的输出全部合法，没有一次回退。问题不在格式，在判断。
- 先推理后选择在决策基准上有明显作用，在这个场景里却没有，原因是这里的题更难，见第六节"与闭环实验是否一致"。
- 之前逐条核对过 Qwen 的一次运行：51 次选择全部选了当前也是最快的路线，其中只有 23 次恰好对车主最划算。它给出的理由说的是"符合车主的时间价值"，但选择从不随时间价值变化。

### llm_persuasion：LLM 扮演的车主如何回应提议

瓶颈场景（220 人，与 bottleneck 实验相同），车为 L3，车主只有"回应车辆提议"这一项权限。DeepSeek-Flash 5 个种子，Qwen 3 个种子。时间和成本两列的括号内是与同批种子的效用模型车主的配对差值。

| 车主的决策模型 | 提议带解释 | 种子数 | 提议次数（合计） | 被接受 | 接受率 | 平均出行时间（秒） | 广义成本（美元） |
| - | - | - | - | - | - | - | - |
| 效用模型（基准） | 是 | 5 | 553 | 195 | 35% | 1363 | 9.13 |
| DeepSeek-Flash，先选择后说明 | 否 | 5 | 473 | 473 | 100% | 1055 (−308 ± 66)* | 7.74 (−1.39 ± 0.23)* |
| DeepSeek-Flash，先选择后说明 | 是 | 5 | 480 | 473 | 99% | 1061 (−302 ± 73)* | 7.77 (−1.36 ± 0.30)* |
| DeepSeek-Flash，先推理后选择 | 否 | 5 | 530 | 439 | 83% | 1115 (−249 ± 74)* | 7.98 (−1.15 ± 0.24)* |
| DeepSeek-Flash，先推理后选择 | 是 | 5 | 540 | 408 | 76% | 1149 (−214 ± 66)* | 8.15 (−0.98 ± 0.29)* |
| 效用模型（基准，前 3 个种子） | 是 | 3 | 334 | 122 | 37% | 1380 | 9.21 |
| Qwen2.5-7B，先选择后说明 | 否 | 3 | 287 | 287 | 100% | 1057 (−323 ± 150)* | 7.76 (−1.45 ± 0.50)* |
| Qwen2.5-7B，先选择后说明 | 是 | 3 | 287 | 287 | 100% | 1057 (−323 ± 150)* | 7.76 (−1.45 ± 0.50)* |

- **默认格式下 LLM 车主几乎全盘接受**：Qwen 287 次全部接受，DeepSeek-Flash 接受 99% 到 100%。DeepSeek-Flash 先推理后选择时拒绝了 17% 到 24%；效用模型只接受 35% 到 37%。
- **如实的解释没有提高接受率。** Qwen 带不带解释的两组逐种子完全相同。闭环里车的留言总是如实的，夸大留言的作用只能在决策基准里测（第六节）。
- **接受得越多，所有人越快。** 平均出行时间和广义成本都随接受率下降。对个人不划算的换乘，在这个瓶颈上减少了过桥的车，对整体有利。所以这里的"全盘接受"改善了系统结果，却不说明模型判断得好：在基准里，Qwen 连更慢的提议也一律接受，DeepSeek-Flash 在留言被夸大时接受了其中两成多。
- **此前的版本已作废。** 2026-11-10 之前这个实验用 120 人，并且受车辆算法那个比较错误的影响（见 bottleneck 一节），车主看到的"继续开车要多久"偏长。修正后 120 人时每次运行只剩约 6 次提议，所以改用 220 人重跑。

### 推理速度与提速（2026-11-09 实测）

一次运行里，每个有人要决策的时刻都要等模型一次，所以耗时约等于"有决策的时刻数 × 每次调用的时间"。400 人的城市场景里，出行者和车辆共 896 次决策分散在 572 个时刻，同一时刻内并发最多只能快 1.6 倍；真正有效的是缩短单次调用和让多次运行同时进行。

用 `experiments/bench_llm.py` 把 32 个真实决策点（覆盖 9 种主体与触发原因的组合，输入约 750 个 token）原样发给两个模型：

| 模型 | 要求附理由 | 同时请求数 | 每次决策（秒） | 每秒完成决策数 | 合法回复 | 每千次决策（美元，估算） |
| - | - | - | - | - | - | - |
| Qwen2.5-7B（本机） | 是 | 1 | 2.5 | 0.39 | 100% | 0 |
| Qwen2.5-7B（本机） | 是 | 8 | 4.9 | 1.54 | 100% | 0 |
| Qwen2.5-7B（本机） | 否 | 1 | 1.3 | 0.74 | 100% | 0 |
| Qwen2.5-7B（本机） | 否 | 8 | 4.0 | 1.91 | 100% | 0 |
| DeepSeek-Flash | 是 | 1 | 1.2 | 0.83 | 100% | 0.20 |
| DeepSeek-Flash | 是 | 8 | 1.3 | 6.2 | 100% | 0.11 |
| DeepSeek-Flash | 是 | 32 | 1.2 | 23.1 | 100% | 0.11 |
| DeepSeek-Flash | 否 | 1 | 0.94 | 1.06 | 100% | 0.17 |
| DeepSeek-Flash | 否 | 32 | 1.0 | 23.5 | 100% | 0.07 |

- **DeepSeek 单次调用快一倍**（1.2 秒对 2.5 秒），不附理由时差距缩小（0.94 秒对 1.3 秒）。
- **DeepSeek 的并发几乎不排队**：32 个同时请求时单次仍是 1.2 秒，总吞吐每秒 23 次，是本机 Qwen 最高吞吐的 12 倍以上。官方给的并发上限是每个账户 2500。

- 不要求附理由，Qwen 单次快一倍，DeepSeek 快两成。输出本身只占 DeepSeek 耗时的一小部分，其余是网络和排队。
- 保持连接不断开，DeepSeek 每次调用省约 0.1 秒（1.31 秒降到 1.21 秒）。
- 费用按高峰期标价和 7.2 的汇率折算，是估算值。本次全部 DeepSeek 测试（约 1100 次调用）估算合计 0.2 美元左右。

两个 LLM 实验的总耗时（按 2026-11-09 的设置，llm_persuasion 当时是 120 人；现在是 220 人，DeepSeek-Flash 5 个种子、四个 LLM 组用时 283 秒）：

## 六、决策基准：同一批受控的决策点

闭环实验有两个弱点。其一，每个模型遇到的决策点各不相同，由它自己前面的选择决定。其二，决策点的难度不受控：收费场景里的选择大多是四条路线、差额只有两毛钱，模型一旦失败，看不出是败在哪里。决策基准把决策点固定下来，交给每一个决策模型。

```bash
.venv/bin/python experiments/benchmark.py --llm deepseek deepseek-thinking deepseek-pro qwen-local
```

任务定义在 `agmsim/benchmark.py`，每道题的回答存在 `experiments/results/benchmark/`，完整的表在 `experiments/results/benchmark.md`。

### 做法

1. **题目取自仿真。** 每个任务先跑一小段仿真，取一条真实出现的观测做模板，所以题目的格式、字段和提示词与仿真里完全一样。
2. **数值按析因设计替换。** 只改与问题有关的数字（时间、收费、票价、当事人的时间价值、车的留言），其余不动。三个任务用同一个人设（35 到 49 岁、通勤）。
3. **标准答案由当事人自己的偏好算出。** 选路按"收费 + 里程成本 + 时间价值 × 时间"取最小；换乘按时间价值乘以省下的时间与票价比较。
4. **任何决策模型都能测。** 题目走与仿真相同的接口：给观测，收决策，按许可的行动校验。规则、算法、LLM、插件都一样。回复始终无效时按"没有回答"计，执行默认行动，不把回退策略的选择算给模型。

| 任务 | 谁决策 | 题数 | 变化的因素 |
| - | - | - | - |
| route_delegation 按车主偏好选路 | 车（L2） | 192 | 车主的时间价值是临界值的 1/3 到 3 倍（六档）；当前路线是收费的还是免费的；是否多列两条更慢的收费路线；8 组路线 |
| suggestion_response 回应换乘提议 | 出行者 | 171 | 比继续开车早到 −6 到 +20 分钟（七档）；时间价值 8、20、50 美元/小时；车的留言：没有、如实、多说 8 分钟；3 组换乘方案 |
| transfer_proposal 是否提议换乘 | 车（L3） | 108 | 省时 1 到 22 分钟（六档）；车主的时间价值三档；是否另有一条比当前路线快 6 分钟的开车路线；3 组换乘方案 |

**灵敏度**是每个任务的主指标：该行动对当事人有利时采取它的比例，减去不利时采取它的比例。总是做、从不做、随机做都得 0，完全按偏好行事得 1。参照模型给这把尺子定了两端：只求快的规则 0，按车主成本选路的算法 1，效用模型车主 1。

换乘的两个任务里，"值得"指即使把候车和步行算得更难熬（效用模型的权重）仍然划算，"不值得"指只算时间和票价都不划算，两者之间的题不计分。

用量：DeepSeek 每组（471 题）用时 24 到 71 秒，九组按标价估算共 1.65 美元（Flash 0.25，思考模式 0.56，V4-Pro 0.84）；Qwen 每组 2 到 6 分钟。加上闭环实验和下面的逐点核对，当天 DeepSeek 约 1.2 万次调用，估算合计 4.0 美元。

### 看到了什么

- **基准把模型拉开了。** 同一个任务上灵敏度从 0 到 0.94，而此前的闭环实验里 Qwen 和 DeepSeek-Flash 都和"只求快"的规则一样，分不出高下。
- **回答格式的影响比模型大小更大。** 更大的 V4-Pro 在默认格式下选路灵敏度是 0.00，192 题全部选了付费；改成先推理后选择是 0.70。Flash 从 0.16 升到 0.66。开启思考模式后是 0.83 到 0.84，与格式无关。
- **默认格式下的理由是事后补的。** 一道题里车主的时间价值是 8 美元/小时，收费 2 美元能省 5 分钟。Flash 在默认格式下选了付费，理由是"按车主每小时 8 美元的时间价值，值得"；先推理后选择时，它对同一道题算出 5 分钟只值 0.67 美元，选了免费路线。192 题里默认格式答错而先推理答对的有 54 题，反过来的有 6 题。
- **Qwen2.5-7B 三个任务都是 0。** 选路时它几乎总是换离当前路线，与车主的时间价值无关：只给选择时，当前路线免费的 96 题全部改走收费路线，当前路线收费的 96 题有 87 题改走免费路线。对提议，前两种格式下它一律接受，包括比继续开车慢 6 分钟的。作为车，前两种格式下它从不提议；先推理后选择时，没有别的开车路线就提议，有就不提议，同样与车主无关。它的算术也不可靠，例如把"8 分钟、每小时 5 美元"算成 40 美元。
- **过度依赖可以测出来，但这一版的分辨力有限。** 对更慢的提议，没有留言时 DeepSeek 的九种配置都是 0% 接受。留言谎称能早到 8 分钟后，V4-Pro（默认格式）接受了一半（18 题里 9 题），理由照抄留言："公交能省大约 8 分钟"；Flash 接受 22% 到 28%；先推理或开启思考后降到 0%。按全部"不值得"的题算，上升幅度的区间都跨过或接近 0，要下结论需要更多题。
- **多列两条路线就会出错。** Flash 先推理后选择，只有两条路线时选对 95%，多列两条更慢的收费路线后降到 71%；思考模式是 96% 和 89%。
- **另有一条更快的开车路线时，不带思考的模型不再提议值得的换乘**（0% 到 8%，V4-Pro 先推理时 42%），它们直接改走那条路线；思考模式仍有 77% 到 92% 提议。
- **人设里没解释的字段被误用。** 车看到的车主信息里有"耐心 8 分钟"（指愿意等车多久），提示词没有向车解释这个字段。思考模式在选路上的错误大多与它有关：先选择后说明时答错 15 题，其中 13 题的理由提到了耐心，把它当成"最多能多开 8 分钟"。这是观测设计的问题。核对：用 `extra_instructions` 给车加一句话，说明耐心指等公交的时间、与选路无关，其余不变，思考模式的灵敏度从 0.84 升到 0.98，错题从 15 道降到 2 道；Flash 先推理后选择没有变化（0.66），它的错不在这里。这句话还没有加进默认提示词，上表都是不加时的结果。
- **内置算法在提议任务上只有 0.43**，因为它只看省不省时间。加上 `weigh_fare: true`（按车主的时间价值比较票价）后是 1.00。

### 与闭环实验是否一致

`experiments/insitu.py` 把 llm_alignment 场景里出现的 503 个"付不付费"决策点逐个拿出来，不带历史，单独交给模型，按同样的方法计分：

| 决策模型 | 闭环：一致率 | 闭环：灵敏度 | 逐点：一致率 | 逐点：灵敏度 |
| - | - | - | - | - |
| 规则（只求快） | 49.0% | 0.15 | 46.7% | 0.03 |
| DeepSeek-Flash，先选择后说明 | 49.6% | 0.16 | 54.3% | 0.17 |
| DeepSeek-Flash，先推理后选择 | 50.7% | 0.18 | 54.9% | 0.18 |
| DeepSeek-Flash，思考模式 | 80.9% | 0.65 | 82.5% | 0.68 |
| Qwen2.5-7B，先选择后说明（3 个种子，152 个决策点） | 51.4% | 0.15 | 55.3% | 0.16 |
| 算法 | 100% | 1.00 | 100% | 1.00 |

- **两种测法结论相同**：Flash 不带思考时接近规则，思考模式明显更好。闭环里测到的，就是模型在单个决策点上的判断。两列的数字不完全相等，因为闭环里每一组面对的决策点是它自己跑出来的，逐点打分用的是算法那一组的决策点。
- **基准里先推理后选择是 0.66，到了这个场景只有 0.18。** 原因在题目：503 个决策点里 456 个列出三条以上路线，最优与次优的差额中位数只有 0.20 美元，而且收费路线同时更短，要把省下的里程成本算进去。基准的分项（四条路线时 71%）提示了这个方向，但设计题的差额普遍更大，没有覆盖到这么小的差额。下一版应加入小差额的题。
- 思考模式在基准上是 0.84，在这个场景是 0.65 到 0.68，同样是场景里的题更难。

### 限制

- 只测了两家的模型：本机的 Qwen2.5-7B，DeepSeek 的 Flash、Flash 思考模式（最低档）和 V4-Pro（未开思考）。
- 提示词没有调优，每题在温度 0 下只问一次，没有测同一事实的不同措辞。
- 区间按题目数近似计算，而同一任务的题共用几组设计，实际的不确定性更大。
- "值得"与"不值得"的界线用了效用模型的候车和步行权重，这些权重是假设值。出行者的提示词要求"按这个人会做的选择来选，而不是按优化器"，所以出行者一侧的"不值得"只取了连时间和票价都不划算的题。
- 夸大留言只有一种写法（多说 8 分钟）。
- 三个任务只覆盖车和出行者，公交、充电站和运营方还没有任务。

## 七、日计划：MATSim 的行动机制，加上当天改计划

2026-11-10 新增。机制说明见 README 的 "Day plans" 一节。这里只记实验。

### 场景

`experiments/scenarios/evening.yaml`：一条河把城分成两岸，两座桥。240 人下午在西岸上班，17:00 到 18:00 之间下班（17:30 前后最集中），全部开车回东岸的家。一半人路上要接孩子（必须在计划到达时间之后 5 分钟内开始，否则算迟到），一半人要办一件事（那个地方 18:20 关门，可以不办）。17:05 起一座桥几乎封闭，持续 70 分钟。车都是 L1（会按路况改道），各组相同。

没有事故时，计划照写的执行不出问题：没人迟到，也没有人被触发复查。所以各组的差别只来自对这次突发事故的反应。

### day_plan：当天改计划能挽回多少

| 实验组 | 计划得分(美元) | 人均迟到(分) | 迟到人数 | 复查次数 | 改动次数 | 平均出行时间(秒) |
| - | - | - | - | - | - | - |
| 照计划执行（基准） | 227.4 | 0.55 | 20.8 | 0 | 0 | 483 |
| 当天调整 · 算法 | 227.7 (+0.271 ± 0.077)* | 0.32 (−0.23 ± 0.054)* | 16.9 (−3.9 ± 1.4)* | 234 | 24.4 | 485 (+1.4 ± 2.8) |
| 无事故 · 照计划执行 | 230.7 (+3.32 ± 0.27)* | 0 | 0 | 0 | 0 | 240 |

10 个种子。得分是 MATSim 的计划得分换算成美元后的人均值；绝对值里绝大部分是上班和在家的固定价值，要看的是差值。

- **事故让每人损失 3.32 美元**，主要是路上多花的时间（出行时间从 240 秒翻倍到 483 秒）。
- **算法当天改计划挽回 0.27 美元，约 8%**，人均迟到时间减少四成。每次运行 234 次复查里只改了 24 次，改法几乎全是"提前下班"（三个种子里 64 次改动，58 次发生在上班时），为的是赶上接孩子或赶在关门前到。
- **挽回得不多，是因为大部分损失是改计划改不掉的**。推演只用当前路况，看不出"晚点走能躲开拥堵"，所以没有时间约束的人无论几点走，推演出来的结果都差不多。
- **乱改有害**。算法早先的版本只要推演结果好一点就改，没有时间约束的人也频繁改出发时间，实际得分反而比不改低 0.24 美元，其中直接回家的人改了之后平均少 0.59 美元（5 个种子，在场景定稿前的参数下测得）。现在的算法只在推演收益达到 0.5 美元时才改。这给了后面评价 LLM 的口径：不只看"该改时改了没有"，也看"不该改时有没有乱改"。

### llm_day_plan：把"当天改计划"交给 LLM

同一场景，出行者的决策模型换成 LLM。只有"计划复查"这一类决策点交给模型（各组相同的 3 个种子，每次运行约 200 次复查）。指标分两层：

- **决策层**：每次复查按本人的打分口径算出各改法的推演价值。"该改"指最好的改法比不改至少多 0.5 美元。灵敏度 = 该改时改了的比例 − 不该改时改了的比例，照计划执行为 0，算法为 1。
- **结果层**：这一天实际过下来的计划得分。

| 决策模型 | 该改时改了 | 不该改时改了 | 灵敏度 | 每次运行改动次数 | 实际计划得分（与照计划执行相比，美元） | 人均迟到(分) |
| - | - | - | - | - | - | - |
| 照计划执行（MATSim 的默认行为） | – | – | 0（按定义） | 0 | 基准 | 0.49 |
| 算法（按本人得分推演） | 100% | 0% | 1.00 | 21 | +0.22 ± 0.40（10 个种子：+0.271 ± 0.077*） | 0.28 |
| Qwen2.5-7B（本机，先选择后说明） | 89% | 92% | −0.03 | 203 | −1.16 ± 1.07* | 0.61 |
| DeepSeek-Flash（先选择后说明） | 94% | 26% | 0.68 | 68 | −0.07 ± 0.67 | 0.34 |
| DeepSeek-Flash（先推理后选择） | 83% | 12% | 0.71 | 41 | +0.03 ± 0.34 | 0.30 |
| DeepSeek-Flash（思考模式） | 94% | 14% | 0.80 | 43 | +0.245 ± 0.057* | 0.26 |

3 个种子，每个模型约 600 次复查，全部得到有效回复，没有回退。实际得分一列是逐种子配对差值 ± 95% 置信区间半宽，`*` 表示区间不含 0。原始表在 `experiments/results/llm_day_plan*.md`。

看到了什么：

- **这个任务能把模型拉开**，排序与第六节的决策基准一致：Qwen2.5-7B 的灵敏度是 0，Flash 约 0.7，思考模式 0.8。
- **Qwen 几乎每次被问到都改计划**，不管该不该改。结果是自己的计划得分比完全不改还低 1.16 美元，而且因为大家都提前出发挤在一起，平均出行时间多了 59 秒（±54，显著）。"让 LLM 来调整"并不自动带来好处，调得不对比不调更差。
- **Flash 该改时基本会改，问题在不该改时也改**（12% 到 26%）。看了一个种子的全部决策：多数多余的改动推演收益只有 0 到 0.2 美元，例如"早走 1 分钟没有风险"；也有真错，例如把"优先级 2"理解成"每多待一分钟的价值翻倍"，在办事地点多待了半小时，按本人口径亏 3.6 美元。后一种是提示词措辞不清造成的，尚未修改。
- **只有思考模式的实际得分显著高于照计划执行**（+0.245 美元），与算法（+0.22）相当。它的多余改动和先推理后选择差不多，但该改时漏得更少。
- **代价**：思考模式每次决策约 1070 个输出 token，600 次调用花了 0.91 美元；非思考的 Flash 两种格式共 1233 次调用花了 0.24 美元；Qwen 在本机 3 次运行用了 25 分钟。本节 DeepSeek 合计约 1.19 美元。

### 与 MATSim 的做法相比

MATSim 的主体在一天之内不做判断：计划写好就照做，改进靠把同一天重演几十到几百次，每次随机改一部分计划，再按得分留下好的。这对"每天都这样"的拥堵有效，对当天才发生的事故无能为力，除非另写当天重规划的代码。这里把"改计划"变成一次决策，一遍仿真就能对突发情况作出反应；代价是决策质量取决于决策模型，以及给它的信息。本节的结果说明两点都不能省：模型不够好时（Qwen）不如不改，信息不够时（推演只看当前路况）连算法也只能挽回一小部分。

### 限制

- 只有 3 个种子，实际得分的区间很宽；能下结论的主要是决策层的比例（每个模型约 600 次复查）。
- 推演假定路况保持现状，没有预测；出行途中不能改计划；可做的编辑只有"改离开时间"和"取消可选活动"两种。
- 没有实现 MATSim 的逐日迭代作为参照，所以还不能回答"LLM 一遍仿真能达到迭代多少轮的水平"。
- 出行者的提示词要求"按这个人会做的选择来选，而不是按优化器"，而这里的评分口径是本人的打分函数，两者并不完全一致。
- 打分参数取 MATSim 的默认值，活动的优先级和典型时长是场景里假设的，未经标定。
- "该改"的界线（推演收益 0.5 美元）是假设值，与算法的门槛相同，所以算法的灵敏度按定义为 1。


## 八、信号灯与协调者

2026-11-11 新增。物理上，有信号灯的路口在每条进口道末端设停车线：所在方向不是绿灯时车停在线后排队（仍占用该路段，所以排队也会拖慢路段），绿灯时按饱和流率先到先走，切换绿灯有几秒全红。信号灯是一类新主体（`signal`）；协调者就是原来的运营方（`operator`），新增了"看到哪里慢、各方向在灯前等了多久"和两种对信号灯的指令。

### 场景

`experiments/scenarios/signals.yaml`（与内置场景 `city_signals` 相同）：6×6 路网，32 个路口有信号灯（四个角没有），600 人开车，四分之三的出行沿某一行从一侧穿到另一侧，所以东西向车流远多于南北向。固定配时下两个方向累计等待为 12502 对 2765 车·秒。

### signals：灯自己有 agency，还是协调者指挥

| 实验组 | 平均出行时间(秒) | 平均车速(英里/时) | 每次过灯等待(秒) | 被红灯拦下的比例 | 协调者指令数 |
| - | - | - | - | - | - |
| 灯 L0（固定配时，基准） | 163.2 | 20.33 | 6.48 | 73% | 0 |
| 灯 L1（按本路口排队） | 141.8 (−21.4 ± 0.7)* | 23.42 (+3.09 ± 0.09)* | 1.95 | 19% | 0 |
| 灯 L2（固定配时，听协调者）· 协调者 L2 | 154.0 (−9.2 ± 0.9)* | 21.56 (+1.23 ± 0.12)* | 4.83 | 31% | 5.5 |
| 灯 L0 · 协调者 L2 | 163.2 (+0 ± 0) | 20.33 | 6.48 | 73% | 1 |
| 灯 L2（按排队，听协调者）· 协调者 L2 | 141.8 (−21.4 ± 0.7)* | 23.42 (+3.09 ± 0.10)* | 1.97 | 19% | 7.8 |

10 个种子，括号内为与基准组的逐种子配对差值 ± 95% 置信区间半宽。没有信号灯时平均出行约 133 秒，但那是路口不产生任何延误的情形，不能作为对照。

看到了什么：

- **灯自己决策效果最大**：每次过灯的等待从 6.5 秒降到 2.0 秒，被拦下的车从 73% 降到 19%。
- **协调者可以部分替代灯自身的智能**：灯只按固定方案走、但肯听协调者时，协调者看到东西向等待远多于南北向，让全网偏向东西向，挽回了约四成（9.2 对 21.4 秒）。
- **交互需要双方都有 agency**：灯是 L0 时，协调者发了指令也没有任何效果。这与 incident 实验的结论同构。
- **灯已经会自己决策时，协调者不再增益**：两者在这个场景里是替代关系。

### 让 LLM 管信号灯（小规模检查）

用 `mix` 让 32 个路口中的 3 个由 DeepSeek-Flash（先推理后选择）决策，其余仍用算法，单个种子：

| 这 3 个路口由谁决策 | 每辆车过灯等待(秒) |
| - | - |
| 固定配时 | 7.36 |
| 算法 | 2.81 |
| DeepSeek-Flash | 2.52 |

135 次模型调用全部得到有效回复，没有回退，花费 0.03 美元，用时约 3 分钟。3 个路口各 200 辆车、一个种子，只能说明 LLM 能胜任这类决策，不足以比较它和算法谁更好。到达最大绿灯时只剩"切换"一个选项，这种决策点不调用模型。

### 调试中发现并改正的两处

- 有决策权的信号灯每 10 秒复查一次，按固定方案本该 30 秒切换的绿灯会拖到 38 秒，使"固定方案 + 有权限"反而比纯固定配时差 9 秒。现在复查时刻对齐方案的切换时刻，两者相同（162 对 163 秒）。
- 协调者最初看的是"此刻各方向排队数"，这个数随相位剧烈跳动，它每次复查都在偏向东西、取消、偏向南北之间来回切换。现在看的是上次复查以来累计等待的车·秒。

### 限制

- 协调者的优势只在灯自身不智能时出现。需要全局信息才能解决的情形（排队溢出堵住上游路口、绿波协调）目前的物理模型里没有：排队不会堵住上游路口，相邻路口之间也没有相位差的概念。
- 每个路口只有东西、南北两个相位，没有左转相位；车辆选路时不考虑信号灯的延误。
- 通行能力按 `network.capacity_scale` 缩放，一辆模拟车代表多辆真实车时放行是离散的。
- 协调者的两种指令（偏向某方向、要求某路口放行）中，本实验里起作用的主要是前者。


## 九、按需车

2026-11-11 新增。按需车是一类新主体（`ondemand`）：出行者叫车，平台把每个请求派给最近的空车，车去接人、送到、收车费。出行者一侧多了"叫车"这个出行方式，等车时可以放弃；等车时间计入"平均等待时间"。

等级沿用存档里早期版本的划分，这次实现了其中三项：L1 按路况改道；L2 权衡后可以拒单（被拒的请求转给下一辆最近的空车）；L4 空闲时自己决定去哪里等。早期版本里的自行定价（L3）、自己抢单和充电没有搬过来。

### 场景

`experiments/scenarios/ondemand.yaml`（与内置场景 `city_ondemand` 相同）：6×6 路网，300 人都没有私家车，50 辆按需车，可以叫车或步行；六成出行在第 10 到 25 分钟从中心一个节点出发（场馆散场），其余均匀分布。车送完人会停在外围，而下一批请求在中心。

### ondemand：改道、拒单、主动调度各带来什么

| 实验组 | 平均等车(秒) | 乘客放弃叫车 | 拒单次数 | 调度次数 | 空驶里程占比 | 车队利润(美元) | VMT(英里) |
| - | - | - | - | - | - | - | - |
| 车 L0（接所有派单，原地等，基准） | 197.9 | 4.7 | 0 | 0 | 40.9% | 1032 | 489.8 |
| 车 L1（按路况改道） | 187.5 (−10.4 ± 5.3)* | 3.9 | 0 | 0 | 40.3% | 1036 | 486.0 |
| 车 L2 · 逐利（每分钟净收入低于 0.6 美元就拒） | 176.9 (−21.0 ± 6.0)* | 2.5 (−2.2 ± 1.6)* | 111 | 0 | 38.6% (−2.3 ± 0.7)* | 1046 (+14 ± 5)* | 474.2 (−15.6 ± 5.7)* |
| 车 L2 · 服务（有拒单权但不用） | 187.5 (−10.4 ± 5.3)* | 3.9 | 0 | 0 | 40.3% | 1036 | 486.0 |
| 车 L4 · 服务（空闲时主动调度） | 184.5 (−13.4 ± 12.2)* | 3.1 | 0 | 180 | 53.5% (+12.6 ± 1.7)* | 985 (−47 ± 14)* | 625.1 (+135 ± 15)* |

10 个种子，括号内为与基准组的逐种子配对差值 ± 95% 置信区间半宽。出行完成率各组均为 99.9%。

看到了什么：

- **改道**把平均等车缩短 10 秒。
- **逐利的车拒单，乘客反而等得更短**（再减 11 秒），空驶和总里程也减少，车队利润略增。原因在平台的派单规则：车紧张时，"最近的空车"可能在很远处，让它长途去接会占用这辆车很久；它拒掉之后，请求往往等到一辆更近的车空出来。这与网约车研究里"长距离接驾拖垮系统"的现象一致。这里的"逐利"是算法里设定的门槛，不是车真的在比较长期收益。
- **有拒单权但目标是服务的车不拒单**，结果与 L1 完全相同：权限相同，目标不同，行为不同。
- **主动调度没有带来可靠的额外好处**：相对 L1 只多减 3 秒且不显著，空驶占比却从 40% 升到 53%，总里程增加 28%，利润下降。调度依据是"最近 5 分钟哪里叫车多"，散场结束后这个信号就过时了。

### 让 LLM 管按需车（小规模检查）

用 `mix` 让 50 辆车中的 5 辆由 DeepSeek-Flash（先推理后选择）决策，等级 L2、目标为逐利，其余 45 辆用算法，单个种子：

| 谁在决策 | 每车接单 | 每车拒单 | 每车收入(美元) | 空驶占比 |
| - | - | - | - | - |
| DeepSeek-Flash（5 辆） | 6.6 | 0 | 28.8 | 34% |
| 算法（45 辆） | 5.5 | 1.1 | 24.9 | 37% |

33 次派单全部得到有效回复，没有回退，花费不到 0.01 美元。模型一单都没有拒：它的理由是"这单净收入为正，拒掉可能丢掉这笔收入"。也就是说，同样被告知"最大化净收入"，模型按"这一单赚不赚"来判断，而算法按"每分钟赚多少是否过线"来判断。5 辆车、一个种子，只说明 LLM 能胜任这类决策并且判断方式与算法不同，不足以比较优劣。

### 限制

- 一辆车一次只载一位乘客，没有拼车；车费是固定公式，车不能自行定价；车队不用充电。
- 平台只有"最近空车"一种派单规则，没有批量匹配；协调者目前不参与派单。
- 出行者放弃叫车后不会再次叫车（否则只是排到队尾），只能步行、改乘其他方式或放弃出行。
- 日计划的行程推演里没有考虑叫车。
- 调度和拒单的门槛（0.6 美元/分钟、最近 5 分钟的请求）是假设值。


## 十、场所（POI）与外部事件

2026-11-11 新增。这一节不是 agency 的对比，而是检验两块新的"物理设定"是否起作用。

**场所**：有名字、有类型（上班、购物、学校、医疗、休闲）、可带营业时间的地点，落在路网节点上，对所有种子都相同。开启 `demand.to_pois` 后，出行按目的去对应类型的场所，越近、权重越大的越容易被选中；日计划里的活动也可以放在某类场所，并继承它的营业时间。

**外部事件**（配置里写在 `events` 下）：

| 事件 | 作用 |
| - | - |
| 路段受阻（原有） | 指定路段限速或封闭一段时间 |
| 天气 | 全部道路和步行变慢；所有主体的观测里都能看到天气；内置选择模型在此期间把等待和步行看得更重 |
| 需求突增 | 一段时间内从某个场所出发（或前往它）的额外出行，例如散场 |
| 场所提前关门 | 人们计划在那里做的事到时结束；有权改日计划的人被告知并复查计划 |
| 运行中改 agency（原有） | 到某一时刻改变某类主体的等级 |

### 场景

`experiments/scenarios/places.yaml`（与内置场景 `town_places` 相同）：6×6 路网，16 个场所（6 处上班地点、4 家商店、2 所学校、1 家诊所、体育场和另外 2 处休闲场所），320 人按出行目的去对应的场所；一半人有私家车，另有一条公交线和 30 辆按需车。运行中三件事：17:20 到 18:00 大雨（道路速度 ×0.75，步行 ×0.85，等待和步行的难受程度 ×1.8）；17:30 到 17:45 体育场散场，多出 120 次出行；17:35 到 18:05 体育场旁一条路受阻。

### places：三件事各自的影响，以及同时发生

| 实验组 | 平均等待(秒) | 平均出行时间(秒) | 平均车速(英里/时) | 步行占比 | 叫车占比 | VMT(英里) |
| - | - | - | - | - | - | - |
| 平静的一天（基准） | 17.1 | 188.6 | 20.57 | 10.2% | 42.7% | 312 |
| 只下雨 | 23.5 (+6.4 ± 1.7)* | 191.5 (+2.9 ± 4.6) | 17.29 (−3.28 ± 0.08)* | 5.0% (−5.2 ± 0.8)* | 47.8% (+5.1 ± 0.9)* | 319 |
| 只有散场 | 28.7 (+11.6 ± 1.8)* | 208.0 (+19.4 ± 13.3)* | 20.67 | 8.0% | 43.9% | 434 (+122 ± 12)* |
| 只封路 | 17.3 (+0.1 ± 0.2) | 190.5 (+1.9 ± 0.5)* | 20.56 | 10.3% | 42.7% | 315 |
| 三件事同时发生 | 73.9 (+56.8 ± 7.7)* | 267.0 (+78.4 ± 11.0)* | 16.24 (−4.34 ± 0.11)* | 4.3% | 47.1% | 481 (+169 ± 13)* |

10 个种子，括号内为与基准组的逐种子配对差值 ± 95% 置信区间半宽。

看到了什么：

- **下雨改变了出行方式**：步行占比减半，这些人改为叫车；车速整体下降 16%。
- **散场增加了叫车的等待**，对车速几乎没有影响。
- **封路几乎没有影响**：车都是 L1，会绕行。
- **同时发生时不是简单相加**：单独发生时平均等待分别增加 6.4、11.6、0.1 秒，合计 18 秒；同时发生时增加 56.8 秒，约三倍。下雨把步行的人赶去叫车，正好赶上散场的 120 人也在叫车，按需车队一下子不够用。

### 场所提前关门（测试里的小例子）

60 人下班后都要去同一家市场办事（可取消），市场今天 16:40 提前关门。有权改日计划的人被告知后复查计划，一部分取消了办事；不能改计划的人照去，到了发现已关门。有权改计划时，"到了发现关门"的人更少，计划得分更高。这是自动测试里的检查，没有做成多种子实验。

### 让 LLM 扮演的出行者看到下雨（小规模检查）

用 `mix` 让 12% 的出行者（38 人）由 DeepSeek-Flash（先推理后选择）决定出行方式，其余用内置选择模型，单个种子；一次全天不下雨，一次全天下雨：

| 38 位由模型扮演的出行者 | 开车 | 叫车 | 公交 | 步行 |
| - | - | - | - | - |
| 晴天 | 18 | 8 | 3 | 9 |
| 全天下雨 | 18 | 20 | 0 | 0 |

75 次模型调用全部得到有效回复，没有回退，花费约 0.02 美元。下雨时没有人再步行或坐公交，全部改为叫车；模型给出的理由直接引用了观测里的天气信息（"大雨让 10 分钟的步行感觉像 18 分钟，而且会淋湿"）。同一批次里用内置选择模型的 282 人，步行从 32 人降到 6 人。模型的反应比内置模型更彻底，但只有 38 人、一个种子，不能据此下定量结论。

### 限制

- 场所的位置是按类型随机摆放的（对所有种子相同），没有土地利用依据；吸引力只有"权重 × 距离衰减"。
- 天气的三个系数（道路速度、步行速度、难受程度）是场景里假设的。
- 需求突增是在生成需求时加进去的，所以总人数随事件而变；突增的出行去向是均匀随机的。
- 充电站停电、公交停运这类设施故障还没有做成事件。
- 协调者目前不会对天气或突增作出专门的反应。

## 十一、记忆、观测、交互：主体凭什么做决定

agency 等级规定一类主体**可以做什么**。这一节的三项设置规定它**凭什么做**，同样按主体类别配置：

```yaml
agents:
  vehicle:
    agency: L1
    observation: {traffic: local, radius_m: 900}      # 看得到多少路况：none | local | global
    memory: {decisions: 4, traffic_seconds: 600}       # 记得自己最近几次决策；路况记多久
    interaction: {share_traffic: true, range_m: 500}   # 通信范围内的车互相转告路况
```

| 机制 | 设置 | 含义 | 适用 |
| - | - | - | - |
| 观测 | `observation.traffic`、`radius_m` | 当前路况自己看得到多少：看不到、只看周围 `radius_m` 米、全网 | 私家车、按需车 |
| 记忆 | `memory.decisions` | 每次决策时给它看自己最近几次决策和结果 | 全部七类 |
| 记忆 | `memory.traffic_seconds` | 看到或听到的慢路记多久 | 私家车、按需车 |
| 交互 | `interaction.share_traffic`、`range_m` | 通信范围内的车互相转告自己知道的慢路，也转告"已恢复畅通" | 私家车、按需车 |

三项都由框架管理，不放在决策模型里：同一类主体无论由规则、算法、语言模型还是远程服务决定，拿到的观测和记忆完全相同，才能公平比较。此前"记忆"只是 LLM 决策模型内部的一个参数，现在是观测的一部分。

一辆车对每条路的估计按如下顺序得出：看得到的路用当前实际速度；看不到但手里有报告（之前自己看到的，或别的车转告的，且没超过记忆时长）的路用报告里的速度；其余的路按畅通算。车一旦得知自己正要走的路上有一段变慢，就立刻重新考虑路线，不必等到下一次定期检查。这时它的观测里会列出估计所依据的报告，每条带有"多久之前"和"自己看到的还是别的车说的"。没有记忆时，一条报告只保留到下一次交换（10 秒），所以车只知道范围内的车此刻看到了什么，不知道它们听说过什么；有记忆时，消息会一辆传一辆地扩散。

已有的交互渠道不变，仍由等级控制：车向车主提议换乘、协调者向信号灯提要求、协调者发布路况通告、充电站报价、按需车服务向车派单。

### 场景

`experiments/scenarios/crossing.yaml`（内置场景 `two_bridges` 与它相同，只是默认开启了记忆和互通）：东西两岸各有一片 5×4 的路网，由相距 1.6 公里的南北两座桥连接，桥长 1.2 公里，上桥后不能掉头。400 人开车，大多数从西岸去东岸，车都是 L1（会改道），由内置算法决定。第 10 到 40 分钟南桥几乎不通（速度降到 10%）。走哪座桥必须在看到桥之前很远就决定，所以车知道多少直接决定结果。

### knowledge：看得多远、记不记得、互不互通

| 附近 + 记忆 + 互通 | 442.1 (−55.0 ± 9.5)* | 629.8 (−157 ± 34)* | 137.5 (−160 ± 27)* | 951.6 (−89 ± 12)* | 1483 | 76% |

看到了什么：

- **等级相同，知道的不同，结果差一倍多。** 六组的车都是 L1。什么都看不到时这个等级没有任何作用（改道 0 次，915 秒）；全网都知道时 426 秒。
- **记忆单独有用**（−40 秒，补回"只看附近"与"全知"之间差距的 57%）。没有记忆的车在桥头看到堵车后掉头去另一座桥，开出视野就忘了，下一次检查路线时又折回来；改道次数从 297 降到 127，多跑的里程也少了。以种子 1 为例：没有记忆时有 29 辆车改道 3 次以上（最多 16 次），有记忆后没有一辆超过 2 次。
- **互通单独有用**（−36 秒，补回 51%）。桥头的车把情况告诉 500 米内的车，后面的车可以早一个路口转向。
- **两者合起来补回 78%**（−55 秒），比各自单独的效果大，但小于两者相加：已经记住的车不需要别人再告诉一遍。
- 离全知还差 16 秒：消息要靠车带着走，刚出发、周围还没有知情车辆的车仍然不知道。

### knowledge_near：看得更近时

把视野缩到 450 米。这时车在上桥之前看不到桥上的情况，上了桥才知道，而桥上不能掉头：

| 实验组 | 平均出行时间(秒) | 90 分位(秒) | 改道次数 | VMT(英里) | 听到的路况条数 | 听到过的车占比 |
| - | - | - | - | - | - | - |
| 只看 450 米（基准） | 909.1 | 2088 | 21.8 | 841.2 | – | – |
| 450 米 + 记忆 10 分钟 | 909.1 (+0 ± 0) | 2088 | 21.8 | 841.2 | – | – |
| 450 米 + 车车互通 | 556.4 (−353 ± 23)* | 1075 (−1013 ± 69)* | 485.0 | 1067 | 1370 | 66% |
| 450 米 + 记忆 + 互通 | 456.5 (−453 ± 33)* | 656.6 (−1431 ± 63)* | 130.7 | 949.6 | 1657 | 77% |
| 全网路况都知道 | 426.4 (−483 ± 33)* | 575.4 (−1513 ± 63)* | 132.3 | 920.7 | – | – |

看到了什么：

- **只看 450 米和什么都看不到几乎一样**（909 对 915 秒）：看到的时候已经来不及了。
- **记忆单独完全没用**（十个种子的差值都是 0）：车要到桥上才知道堵，这一趟已经改不了，而每辆车只走一趟。
- **互通单独补回 73%**：桥上的车告诉桥头的车。但没有记忆时消息只能传一跳，车反复改道（485 次）。
- **记忆在有互通时才值钱**：在互通的基础上再加记忆又少 100 秒，合计补回 94%。知情的车把消息带到远处再转告，这只有记得住才做得到。也就是说，两个机制单独看一个是 0、一个是 −353 秒，合起来是 −453 秒，不是简单相加。

两张表放在一起：三个机制互相替代。看得够远时记忆和互通都不重要；看得近时，互通替代视野，而记忆决定互通能传多远。

### 补充扫描（4 个种子，未做成正式实验）

- 视野：450 米 940 秒，900 米 498 秒，1300 米 468 秒，2000 米 435 秒，4000 米 430 秒。视野 2000 米时再加记忆和互通只差 2 秒。
- 记忆时长（视野 900 米、有互通）：不记 467 秒，记 1 分钟 447 秒，记 2 分钟及以上都是 446 秒。这个场景里每辆车只走一趟，记忆只需撑过"看到"到"下一次决定"之间的时间；记得更久既没有好处也没有坏处，因为"已恢复畅通"的消息同样会被转告。
- 通信距离（视野 900 米、记 10 分钟）：100 米 459 秒，250 米 457 秒，500 米 446 秒，1000 米及以上 443 秒。

### 让 LLM 开车（小规模检查）

同一场景（视野 900 米、记 10 分钟、有互通），400 辆车的路线决策全部交给 DeepSeek-Flash（先推理后选择），单个种子；一次让它看到自己最近 4 次决策，一次不给它看：

| 私家车由谁决定 | 平均出行时间(秒) | 被问到的决策 | 选了已知最快路线 | 模型调用 | 回退 | 花费(美元) |
| - | - | - | - | - | - | - |
| 内置算法 | 447.4 | 129 | 129 | 0 | – | 0 |
| DeepSeek-Flash，记得最近 4 次决策 | 447.4 | 129 | 129 | 129 | 0 | 0.037 |
| DeepSeek-Flash，不记得 | 447.4 | 129 | 129 | 129 | 0 | 0.023 |

129 次调用全部得到有效回复。模型每一次都选了已知最快的路线，与算法完全一致，所以三次运行的结果相同。这里的选择差别很大（原路线 25 分钟，绕行 8 分钟），不是难题；它说明的是新机制在 LLM 路径上是通的：观测里带着记忆和路况报告，模型能读懂并据此选择。**"记得自己最近的决策"在这个检查里没有带来任何差别**，目前也没有别的实验显示它有用。

### 限制

- 观测范围的设置目前只有"路况"一项，只对自己找路的两类车有意义；其他五类看到什么仍由角色和等级决定。
- 交互是结构化的路况报告，不是任意两个主体之间的自由文本消息；报告的内容总是如实的，没有谎报或出错。
- 车对报告一律照单全收，不会因为报告旧了就打折扣；报告的时间和来源已经写在观测里，但内置算法没有用到。
- "记得最近几次决策"对所有决策模型都可用，但内置的规则和算法都没有用到它，LLM 的小规模检查里也没看到差别。
- 视野按"车所在路段的中点到另一条路段中点的距离"判断，是几何上的简化。
- 实验场景里每辆车只走一趟；记忆在多趟出行（日计划）里的作用没有测。

## 十二、决策记忆：只记得自己做过什么，够不够

上一节的小规模检查里，"让主体看到自己最近的决策"没有带来任何差别。原因在检查的条件：那时车有路况记忆、车车互通，当前观测已经足够，记不记得自己做过什么都得出同样的选择。**决策记忆只有在当前观测不够用时才可能起作用。** 这一节把它放到观测不够的条件下测。

### 条件：车看得见附近，但不记路况、不互通

仍是两座桥的场景（`experiments/scenarios/crossing.yaml`），车只看得到周围 900 米，路况不记、车之间不互通，即上一节 knowledge 实验的基准组。这一组的车会来回折返。种子 1 中一辆车（V112）依次看到的是：

| 时间 | 位置 | 当前路线 | 备选路线 | 选择 |
| - | - | - | - | - |
| 00:16:30 | 桥头前 | 24.4 分 / 2.4 公里 | 10.0 分 / 5.6 公里 | 改道，去另一座桥 |
| 00:19:00 | 已离开桥头 | 8.5 分 / 4.4 公里 | 6.8 分 / 3.6 公里 | 改道（看不到桥了，原来那条路按畅通估计） |
| 00:20:50 | 又到桥头前 | 24.3 分 / 2.8 公里 | 9.8 分 / 5.2 公里 | 改道 |
| 00:22:20 | 已离开桥头 | 8.7 分 / 4.4 公里 | 6.9 分 / 3.6 公里 | 改道 |
| … | | | | 共 14 次 |

每一步单看都是"选已知最快的路"，合起来是原地打转。离开拥堵那一步大多省 12 到 17 分钟，折回去那一步看上去大多只省不到 2 分钟。这辆车的当前观测里没有任何东西告诉它"备选路线就是刚才逃离的那条"；它自己的决策记录里有。

为了让主体知道自己的估计靠什么，这一节起，看不到全网的车会在观测里被告知：自己看得到多远，看不到的路一律按畅通估计（除非手里有报告）。

记忆还多了一个选项 `memory.reasons`：每条记住的决策附带当时决策模型给出的理由（最多 280 个字符）。默认关闭。

### decision_memory：内置算法用上决策记忆

给内置算法加一条只依赖决策记忆的规则（`policy_params: {settle_min: 10, resettle_saving_min: 5}`）：改道后 10 分钟内，再次改道必须能省 5 分钟以上。"上次什么时候改过道"只能从记忆里读到。

| 实验组 | 平均出行时间(秒) | 90 分位(秒) | 改道次数 | 改道 3 次以上的车 | VMT(英里) |
| - | - | - | - | - | - |
| 算法 · 不用记忆（基准） | 497.1 | 786.4 | 297.2 | 30.2 | 1040 |
| 会用记忆的算法 · 记得最近 0 条 | 497.1 (+0 ± 0) | 786.4 | 297.2 | 30.2 | 1040 |
| 会用记忆的算法 · 记得最近 1 条 | 466.4 (−30.7 ± 10.3)* | 723.8 (−63 ± 35)* | 163.0 (−134 ± 28)* | 13.0 (−17.2 ± 5.0)* | 997.7 (−43 ± 12)* |
| 会用记忆的算法 · 记得最近 2 条 | 462.4 (−34.7 ± 9.3)* | 714.8 (−72 ± 25)* | 136.4 (−161 ± 23)* | 5.0 (−25.2 ± 3.2)* | 989.7 (−51 ± 10)* |
| 会用记忆的算法 · 记得最近 4 条 | 460.0 (−37.1 ± 9.3)* | 711.6 (−75 ± 27)* | 122.2 (−175 ± 26)* | 0.2 (−30.0 ± 4.1)* | 984.9 (−55 ± 11)* |
| 会用记忆的算法 · 记得最近 8 条 | 459.7 (−37.4 ± 9.3)* | 710.6 (−76 ± 28)* | 121.5 (−176 ± 26)* | 0 (−30.2 ± 4.3)* | 984.6 (−56 ± 11)* |
| 参照：算法 · 记路况 10 分钟 | 457.0 (−40.1 ± 9.4)* | 703.4 (−83 ± 30)* | 127.1 (−170 ± 26)* | 0 (−30.2 ± 4.3)* | 979.3 (−61 ± 11)* |

10 个种子，括号内为与基准组的逐种子配对差值 ± 95% 置信区间半宽，`*` 表示区间不含 0。

看到了什么：

- **决策记忆在这里有用，而且几乎能替代路况记忆。** 记 4 条时出行时间少 37.1 秒，是"记路况 10 分钟"效果（40.1 秒）的 93%；来回折返的车从平均 30.2 辆降到 0.2 辆。
- **没有记忆，同一个算法什么也做不了。** 记 0 条时十个种子的结果与不用记忆的算法逐一相同。这条规则的全部信息都来自记忆。
- **记几条有讲究。** 只记 1 条时效果打了折扣（−30.7 秒，仍有 13 辆车折返）："忍住不改"本身也是一条决策，会把"刚改过道"那条挤出去，下一次检查时车又不记得了。记 4 条就够，8 条没有更多好处。

### llm_decision_memory：LLM 会不会用自己的记忆

同样的条件，把车的路线决策交给语言模型（先推理后选择；标“思考”的一组用模型自带的推理阶段，回答里只附一句理由），看它在能看到自己最近 4 条记忆时是否不再折返。以下都是**种子 1 的单次运行**，用一次性脚本测得，配置与套件里的 `llm_decision_memory` 各组相同（`experiments/suite.py llm_decision_memory --seeds 1 --llm deepseek --answer reason` 可重跑）。作为对照，同一个种子上：不用记忆的算法 498.7 秒、改道 300 次、29 辆车改道 3 次以上；会用记忆的算法（记 4 条）462.2 秒、改道 119 次、0 辆。

记忆的内容改了三版，每一版都是上一版测出问题之后改的。

**第一版：记下"选了哪个选项"。** 条目形如"00:16:30 选了路线 1，结果：改道"。

| 模型 | 记忆 | 平均出行时间(秒) | 改道 | 忍住不改 |
| - | - | - | - | - |
| DeepSeek-Flash | 4 条，带当时的理由 | 498.7 | 300 | 0 |
| DeepSeek-Flash | 同上，并被要求先回看记忆 | 498.7 | 300 | 0 |
| DeepSeek-Flash（思考） | 4 条，带当时的理由 | 498.7 | 300 | 0 |

三次运行的 300 个决策与不用记忆的算法逐一相同。被要求回看记忆的模型确实读了，但读错了：它写的是"这与我最近一贯选择路线 1 相符"。"路线 1"只是当时的选项编号（路线 0 永远是当前所在的路线），离开当时的观测就没有意义。这是记忆条目的设计缺陷，不是模型的问题。**改正：每类主体自己决定一条决策怎样记入记忆，用事后仍看得懂的话**；路线选择记成"换了路线：离开的那条 24.4 分 / 2.4 公里，换到的那条 10.0 分 / 5.6 公里"。

**第二版：按路线本身描述。**

| 模型 | 记忆 | 平均出行时间(秒) | 改道 | 忍住不改 |
| - | - | - | - | - |
| DeepSeek-Flash | 不记得 | 498.7 | 300 | 0 |
| DeepSeek-Flash | 4 条，并被要求先回看记忆 | 498.7 | 300 | 0 |
| DeepSeek-Flash | 4 条，带理由 | 498.7 | 300 | 0 |
| DeepSeek-Flash | 4 条，带理由，并被要求先回看记忆 | 498.7 | 300 | 0 |
| DeepSeek-Flash（思考） | 同上 | 498.7 | 300 | 0 |
| DeepSeek-V4-Pro | 同上 | 498.7 | 300 | 0 |

六次运行仍与不用记忆的算法逐一相同，更强的 V4-Pro 也一样。模型引用了记忆，但把它当作**先例**："我之前也是因为更快而换路线，这个理由现在仍然成立"。它没有把记忆当作关于路况的证据（"两分钟前我离开的那条路要 25 分钟，现在这条'更快'的备选很可能就是它"）。回头看，记忆里确实少了一环：只有当时怎么想的，没有后来怎么样。**改正：车在下一次查看路线时，如果发现上次选的路线比当时估计的慢 5 分钟以上，这件事作为"结果"记入记忆**（`route_slower_than_reckoned`，写明是哪一次选择、当时估计还要几分钟、现在要几分钟）。

**第三版：加上"后来怎么样"。**

| 模型 | 记忆 | 平均出行时间(秒) | 改道 | 改道 3 次以上的车 | 被问到的决策 | 忍住不改 |
| - | - | - | - | - | - | - |
| DeepSeek-Flash | 4 条 | 498.7 | 298 | 29 | 299 | 1 |
| DeepSeek-Flash | 4 条，并被要求先回看记忆 | 498.0 | 296 | 29 | 298 | 2 |
| DeepSeek-Flash | 4 条，带理由，并被要求先回看记忆 | 491.6 | 249 | 28 | 256 | 7 |

有了结果反馈，模型开始用记忆了，但**大多用反了**。第三行忍住不改的 7 次里查看了 6 次：只有 1 次是对的（离开桥头后，拒绝了那条"看上去快 1.1 分钟"的回头路）；另外 5 次是在桥头、亲眼看到当前路线要 22 到 24 分钟的时候，决定**留在堵车的路线上**，理由是"我最近两次换到'更快'的路线，结果都比估计的慢得多，所以备选路线的估计不可信"。前两行的 3 次也都是这种。它记住了"被骗过"，却把账算在了错的估计头上：不可信的是离开桥头后对原路线的估计，绕行路线的估计一直是准的。带理由的那一组里，模型自己写下的理由仍然用"路线 1"称呼路线，又把第一版的歧义带回了记忆。出行时间少了 7 秒，一个种子上无法与偶然区分；留在堵车里和来回折返本来就差不多慢。

12 次运行共 3,554 次模型调用，全部得到有效回复，没有回退，花费约 1.17 美元。

**第四版：路线有了身份。** 前三版里路线只有时间和里程，而"路线 0"永远指当前所在的路线，模型认不出"这条备选就是我刚离开的那条"。新增选项 `observation.route_roads`（默认关闭）：每条备选路线带上途经的路口序列，记忆里记下的路线也带。

先逐点测（`experiments/insitu_memory.py`）。把算法跑出来的决策点一个个单独交给模型，不带运行环境，便宜而且每个模型面对的题完全相同。种子 1 的事故期间共 288 个点，分三类：

- **该离开**（199 个，抽 40 个）：车在通往堵桥的路线上，已经看到堵车。对的做法是改道。
- **首次折返**（32 个）：车已绕行，看上去最快的备选要回到堵桥；这趟还没吃过亏，记忆里只有"我刚离开了一条要 25 分钟的路线"。对的做法是不回去。
- **吃过亏后的折返**（57 个）：同上，但记忆里已有"上次回去，比估计慢了 20 分钟"。

| 模型 | 给它看什么 | 该离开 | 首次折返 | 吃过亏后的折返 |
| - | - | - | - | - |
| DeepSeek-Flash | 没有记忆，路线带路口 | 40 / 40 | 0 / 32 | 0 / 57 |
| DeepSeek-Flash | 有记忆，路线不带路口 | 40 / 40 | 0 / 32 | 0 / 57 |
| DeepSeek-Flash | 有记忆，路线带路口 | 40 / 40 | 0 / 32 | 16 / 57 |
| DeepSeek-Flash | 同上，并被要求先回看记忆 | 40 / 40 | 0 / 32 | 30 / 57 |
| DeepSeek-V4-Pro | 同上 | 40 / 40 | 0 / 32 | 23 / 57 |
| DeepSeek-Flash（思考） | 同上 | 39 / 40 | 1 / 32 | 48 / 57 |

每组 129 到 131 次调用，没有回退，六组共 0.39 美元。

- **记忆和路线身份缺一不可。** 只有其中一样时 57 个点全错；两样都有才开始对。
- **提醒一句"先回看记忆"有用**（16 → 30），**开启思考更有用**（48，占 84%）。更大的 V4-Pro 不带思考只有 23。
- **没有一个模型能"未雨绸缪"。** 首次折返 32 个点，各配置合计只对了 1 个。模型只从吃过的亏里学，不会从"我两分钟前刚因为堵车离开这条路"推出"它现在多半还堵着"。内置规则连第一次折返也拦住了。
- **认得出路线，认不出路。** 思考模型错的 9 个点全是同一种：它避开了上次吃亏的那条路线，却选了另一条同样要过堵桥的路线（从别的方向上桥）。记忆里写的是"哪条路线慢了"，没有写"慢在哪一段"；后者正是路况记忆记的东西。

再看整趟运行（种子 1，路线带路口，记 4 条，被要求先回看记忆）：

| 私家车由谁决定 | 平均出行时间(秒) | 改道 | 改道 5 次以上的车 | 忍住不改 | 其中对的 |
| - | - | - | - | - | - |
| 算法 · 不用记忆 | 498.7 | 300 | 17 | – | – |
| DeepSeek-Flash，没有记忆 | 498.7 | 300 | 17 | 0 | – |
| DeepSeek-Flash，不提醒回看 | 494.1 | 272 | 15 | 10 | 10 |
| DeepSeek-Flash | 493.1 | 262 | 19 | 26 | 26 |
| DeepSeek-Flash，带当时的理由 | 498.1 | 272 | 18 | 8 | 6 |
| DeepSeek-Flash（思考） | 483.3 | 221 | 5 | 40 | 40 |
| 会用记忆的算法 · 记 4 条 | 462.2 | 119 | 0 | 86 | 86 |

- **方向对了。** 没有路线身份时，模型忍住不改的 10 次里查看了 9 次，8 次是留在堵车里；有了路线身份，三组不带理由的运行共忍住 76 次，全部是拒绝回头路。
- **思考模型把出行时间从 498.7 降到 483.3 秒**，是内置规则效果（462.2）的四成左右。差距来自上面两点：第一次折返拦不住；避开了一条回头路又选了另一条。
- **带上"当时的理由"反而差一些**（8 次里 2 次留在堵车里）。模型自己写的理由里仍然用"路线 1"称呼路线，把歧义带回了记忆。
- 逐点测的排序（思考 > 提醒回看 > 不提醒）与整趟运行一致。

这一轮 11 次运行共 2,191 次调用，没有回退，花费约 0.85 美元，比事先估计的 0.3 到 0.5 美元多：为了分清"用没用记忆"和"用得对不对"，加了逐点测和两次整趟运行。

### 路线身份有没有副作用

路线身份对折返有用，但它要加进每一次选路的观测里。在与“哪条路线是哪条”无关的决策上，它会不会改变模型的决定？`experiments/insitu_identity.py` 取两类决策点（都来自算法驱动的运行），同一个点用几种写法各问一次，逐点比较答案：

- **不带路线身份**（基准）、**带途经路口**、**带代号**（代号见下一小节）；
- **原样再问一次**：同一个问题问两遍，答案自己会变多少；
- **内容不变，只把每条路线的字段倒过来写**（收费、里程、时间的先后顺序反过来）：任何一种写法上的改动，会让这个模型变多少。

两类决策点：

- **收费选路**：llm_alignment 场景里“付不付费”的选择（种子 1 到 3，共 152 个点，该付费 70、不该付费 82）。对的做法是选对车主最划算的路线。这个场景里每辆车只被问一次，所以这些点上没有记忆。
- **提议换乘**：bottleneck 场景里 L3 的车可以向车主提议换乘公交的决策点（种子 1，共 183 个：值得提议 32、不值得 120、两可 31，两可的不计分）。其中 104 个点带有记忆，记忆里的路线也随之带或不带路线身份。

与不带路线身份的那一版相比，答案变了的点数：

- **DeepSeek-Flash 带不带思考，加上途经路口都没有超出底噪的变化。** 配对差值区间都包含 0；答案变动的点数与原样再问一次相当；不带思考的 Flash 在收费选路上 150 个点一个都没变。它们的理由里没有一条提到路口。
- **Qwen2.5-7B 的答案随写法而变，路线身份不是其中最重的一项。** 它原样再问几乎不变（0 和 3 个点）；加上途经路口变 3 和 24 个点，加上代号变 8 和 14 个点；而内容完全不变、只把每条路线的字段倒过来写，就变了 53 和 37 个点。所以它的变化不能说成“路线身份干扰了它”：对这个模型，观测写法上的任何改动都会改掉一部分决策，路线身份属于较轻的一种。
- **两种路线身份对 Qwen 有一个方向相同的影响**：提议换乘的次数从 12 次降到 3 次（只调字段顺序时是 17 次）。途经路口那一格“判断对了”升了 4.7 个百分点，原因是这批点里不值得提议的占多数，少提议就多得分；值得提议的 27 个点，它在各种写法下都只提议了 0 到 2 次。
- **字段的先后顺序本身就是一个有分量的因素。** 默认的顺序是时间、里程、收费；倒过来把收费写在前面，Qwen 在收费选路上的一致率从 55% 升到 79%（改对 45 个点、改错 8 个，选收费路线的从 137 个点降到 86 个），DeepSeek-Flash 从 55% 升到 60%（变了 8 个点，全部是改对）。第五节“不带思考的模型与只求快的规则没有差别”是在默认顺序下得到的，换一种顺序对 Qwen 就不成立。反方向也有代价：提议换乘的点上，时间被挪到最后，Qwen 继续开车时选到最快路线的从 93 个点降到 67 个（共 98 个）。
- **同一个问题问两遍，答案本身就会变。** 温度设为 0 的 Flash 在提议换乘上 150 个点有 11 个前后不同；思考模式（温度不起作用）是 13% 到 15%，它在收费选路上三次提问的一致率分别是 76%、75%、79%。比较两种观测时要先量这个底噪，否则会把它当成效应。
- **代价很小。** 每次调用的输入 token，带途经路口多 7% 到 14%，带代号多 5% 到 7%；DeepSeek 的花费和延迟差别小于各次提问之间的波动。没有 LLM 的运行不受影响：8 个场景开与关的终态完全相同（内置算法不读这些字段），记录体积增加 0.2%。
- **能排除的只是较大的副作用。** DeepSeek 各组的区间半宽在 3.7 到 7.6 个百分点之间，几个百分点以内的影响这个样本量看不出来。只测了两类任务、100 到 150 个点；代号在 DeepSeek 上的副作用、字段顺序在其余各组上的影响都没有测；字段顺序只试了“倒过来”这一种；没有做整趟运行。按需车在现有场景里几乎不出现选路点（一次运行 0 到 1 个），没有测。

### 短代号：把“认出路线”交给框架

途经路口要占一长串，认不认得出是同一条路线还得靠模型自己去比对。`observation.route_names` 换一种做法：每条备选路线带一个代号（A、B、C……），由框架负责让同一种走法在各个决策点上用同一个代号，记忆里的路线也用代号。

- **规则**：一条路线至少一半的长度落在某个已有代号走过的路上，就用那个代号（有多个时取重合最多的），否则得到一个新代号；它自己经过的路随即并入这个代号。所以只差一小段的两条路线共用一个代号，同一条路线再次出现时代号不变，车当前所在的路线沿用它上次选的代号。换了目的地就重新开始，用没用过的代号。
- **给模型的说明**（随观测一起给）：“一个代号代表去目的地的一种走法，同代号的路线是它的变体；代号在每个决策点和你的记忆里含义相同，路线编号则不然。”
- **在两座桥场景里它是否名副其实**（种子 1，300 个选路决策点，对照同一批路线的途经路口检查）：每辆车平均用到 2.0 个代号（最多 3 个），大体对应“走哪座桥”；同一条路线再次出现时代号相同（318 / 318）；车所在的路线代号保持不变（180 / 180）；过堵桥的路线与不过堵桥的路线从不同名（299 / 299）；吃过亏后回堵桥的那条最快路线，全部带着车此前离开过的代号（62 / 62）。
- **它不是什么**：代号说的是走哪一带，不是具体哪条路。在网格上绕开一个事故路段的小绕行，和原路线有一半以上重合，算同一种走法：incident 场景 159 个决策点里有 53 个点，经过事故路段的路线与绕开它的路线同名。“一半”这个界限是设定的，没有调过。

用上一小节同一批决策点重测记忆的使用（都被要求先回看记忆）：

| 模型 | 路线身份 | 该离开 | 首次折返 | 吃过亏后的折返 |
| - | - | - | - | - |
| Qwen2.5-7B | 没有 | 39 / 40 | 2 / 32 | 0 / 57 |
| Qwen2.5-7B | 途经路口 | 21 / 40 | 11 / 32 | 1 / 57 |
| Qwen2.5-7B | 代号 | 31 / 40 | 16 / 32 | 0 / 57 |
| DeepSeek-Flash | 途经路口 | 40 / 40 | 0 / 32 | 30 / 57 |
| DeepSeek-Flash | 代号 | 40 / 40 | 0 / 32 | 16 / 57 |
| DeepSeek-Flash（思考） | 途经路口 | 39 / 40 | 1 / 32 | 48 / 57 |
| DeepSeek-Flash（思考） | 代号 | 40 / 40 | 0 / 32 | 55 / 57 |

- **会推理的模型用代号更好**：48 → 55，而且更便宜（一组 0.058 对 0.091 美元）。用途经路口时它错的 9 个点，全是避开了吃过亏的那条路线、却选了另一条过同一座桥的；代号把这些变体归到了同一个名字下，这类错只剩 1 个。
- **不带思考的 Flash 用代号反而差**：30 → 16。它认出来了，57 条理由全部提到了代号，56 条提到了记忆；但答错的 41 次里有 34 次接着说“那是 A 的另一段（另一个变体）”，然后照旧选了看上去最快的。用途经路口时，它答对的 30 次里有 29 次的理由是“这正是我上次走的那条路线”。路口串让它自己核对出“是同一条”；代号只是告诉它“是同一种走法”，它不当真。
- **说明怎么写有影响，但改变不了这一点。** 说明的第一版写的是“同代号的路线大体走同一批路”，Flash 只对了 9 个（36 次说“另一段”）；改成现在的写法后是 16 个。思考模式两版分别是 54 和 55。
- **Qwen 不用记忆。** 三种写法下，吃过亏后的折返它只对了 0 到 1 个。有了路线身份之后，它“首次折返”对得多了（2 → 11、16），“该离开”却对得少了（39 → 21、31）：它只是更常留在当前路线上，两头一加并没有更好。
- **仍然没有模型会预判**：首次折返，DeepSeek 的各组合计只对了 1 个。

DeepSeek 这部分共 798 次调用，0.27 美元（含说明第一版的三组和上一小节字段顺序的一组），事先估计的是 0.2 美元。没有做整趟运行。

### 结论

- **决策记忆有没有用，取决于当前观测够不够。** 观测够用时（上一节）它不改变任何选择；观测不够时，一条两行的规则靠它补回了路况记忆 93% 的效果。
- **有记忆不等于会用记忆，会不会用取决于记忆里写了什么。** 同一个模型（Flash）在同一批决策点上，只因记忆条目的写法不同，用对记忆的比例从 0 变到 28%（提醒回看后 53%）；开启思考后是 84%。需要同时满足三条：条目脱离当时的观测也看得懂；决策的结果一旦显现就记进去；选项有跨决策点不变的身份。少一条，模型要么不用记忆，要么用反。
- **模型只从结果里学，不做预判。** 即使是最好的配置，也要先折返一次、吃一次亏，才会拒绝回头路。
- **推理能力的影响大于模型大小。** 开启思考的 Flash 明显好于不带思考的 V4-Pro；一句通用的"先回看记忆"能把不带思考的 Flash 提高近一倍。
- **逐点测能预告整趟运行的结果**，而且便宜得多（每组约 0.02 到 0.16 美元，对比整趟 0.06 到 0.33 美元）。
- **观测怎么写，对弱模型的影响可以大过换一个模型。** 内容不变、只调字段顺序，Qwen2.5-7B 在收费选路上的一致率从 55% 变到 79%，与开启思考的 Flash 相当；路线身份对它的影响比这小。DeepSeek-Flash 受写法的影响小得多（150 个点变 0 到 8 个）。
- **“认出这是哪条路线”可以交给框架，模型信不信是另一回事。** 短代号让会推理的模型更好（48 → 55），让不带思考的 Flash 更差（30 → 16）：它要自己比对过路口才认账。所以两种路线身份都留作选项，默认都关闭。

### 限制

- LLM 部分每组只有一个种子、一个场景、一家的三个模型、温度 0，结论只能算观察。`experiments/insitu_memory.py` 和套件里的 `llm_decision_memory` 可以用更多种子和别的模型重跑。
- 两种路线身份（`observation.route_roads`、`observation.route_names`）默认都关闭，此前记录的 LLM 结果都是在没有它们的情况下测的。哪一种更好取决于模型，没有一种对三个模型都好。决策基准的题目是设计出来的路线，没有对应的路口和代号。
- 字段顺序的影响是在做对照时发现的，只试了一种顺序、两类决策点；它对第五、六节各项 LLM 结果的影响没有系统测过。
- "先回看记忆"的提示是通用的一句话，没有试针对这个场景的提示（那等于把规则直接告诉模型）。
- 内置算法的规则（改道后 10 分钟内，省不到 5 分钟就不再改）是针对折返这一种情形写的，两个参数是设定的，没有调过。
- 结果反馈目前只有私家车的路线选择一种；其他主体的决策大多仍然只在行程结束时才有结果。
- 决策记忆在出行者一侧（多段出行里"上次坐这个吃过亏"）的作用没有测。

## 十三、测试床：简化版蒙特利尔

前面各节为每个问题各搭了一个场景，场景越来越多，结果之间不好比。从这一节起，实验集中在一个测试床上，做法类似交通研究里常用的 Sioux Falls 路网：一个小而固定、看得懂的抽象路网，所有实验都在它上面做。

### 路网和场景

- **路网**（`agmsim/montreal.py`，`network: {type: montreal}`）：37 个节点、76 条双向道路。节点是蒙特利尔的街区、立交和各过河通道的对岸（市中心、McGill、高原区、Décarie/A-40、Turcot、Dorval 机场、Anjou、南岸的 Longueuil 和 Brossard、Laval 等）。道路分三类：高速（A-40、A-15 Décarie、A-20、Ville-Marie、A-25 等，90 公里/时，3 车道）、主干道（50 公里/时，2 车道）、桥和隧道（Champlain、Jacques-Cartier、Victoria、Mercier、Lafontaine 隧道，以及去 Laval 的五座桥）。范围约 28 × 27 公里。
- **场景**（`agmsim run montreal`）：工作日早晨 7 点到 9 点。900 名出行者按人口分布出发，去有名字的场所（市中心写字楼、McGill、蒙特利尔大学、机场、医院、Jean-Talon 市场等）；65% 有车；60 辆按需车；四条有独立路权的公交线（对应地铁橙线、绿线和 REM 的南线、西线，画成环线）；内城 13 个路口有信号灯；7 个充电站；一个协调者；7 点半 Décarie 高速上有一起事故。
- **它是什么、不是什么**：位置按街区从地图上读取，长度是直线距离乘 1.2，车速和车道数按道路等级取典型值。它是用来做实验的抽象，不是标定过的城市模型。

基准运行（种子 1）：全部行程走完，平均出行时间 19 分钟，小汽车 62%、公交 20%、按需车 18%，一次运行约 6 秒。

### vehicle_agency：只改私家车的等级

测试床原样（协调者 L1 会发事故通告）：

| L0（基准） | 31.8 | 288 | 9169 | 1256 | 33 |
| L1 | 32.4 (+0.6) | 283 (−5) | 9182 | 1234 (−23) | 33 |

| 车的等级 | 平均车速(英里/时) | VHT(小时) | VMT(英里) | 平均出行时间(秒) | 充电出行次数 |

| L0（基准） | 25.7 | 368 | 9432 | 1425 | 34 |

3 个种子，括号内是与 L0 的配对差值，`*` 表示 95% 置信区间不含 0。

- **在蒙特利尔上，起作用的是 L1（改道）。** 没有别人帮忙时车速从 25.7 升到 30.6 英里/时，车小时少一成多；协调者发了通告之后，这一步只剩 0.6 英里/时。
